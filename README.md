# mp3tagconv

把舊編碼的 MP3 標籤轉成 **ID3v2.4 UTF-8**，並修復檔名／目錄名的編碼問題。

針對繁體中文環境下累積多年的音樂庫設計：同一批檔案裡混著 Big5（含「Unicode 補完計畫」／倚天擴充的日文假名）、Shift_JIS、GBK、EUC-JP、UTF-16……而且全部都被標成 Latin-1。

## 安裝

需要 Python 3.10 以上。

```bash
python -m venv .venv
```

```bash
.venv\Scripts\python -m pip install -e .
```

## 使用方式

**1. 先預覽**（不會修改任何檔案）：

```bash
.venv\Scripts\python -m mp3tagconv convert "D:\Music"
```

會在目前目錄產生 `mp3tagconv-<時間>-preview.txt` 報告，列出每個檔案每個欄位判定的編碼、信心、轉換結果，以及會更名的檔案。報告開頭的「請檢查」區塊集中列出低信心與無法還原的項目。

**2. 確認報告沒問題後套用：**

```bash
.venv\Scripts\python -m mp3tagconv convert "D:\Music" --apply
```

**3. 不滿意可以完全還原：**

```bash
.venv\Scripts\python -m mp3tagconv undo mp3tagconv-undo-<時間>
```

### 選項

| 選項 | 說明 |
|---|---|
| `--apply` | 實際寫入。沒有這個選項就只是預覽 |
| `--report FILE` | 報告輸出路徑 |
| `--undo-dir DIR` | 還原資料存放位置（預設：目前目錄下的 `mp3tagconv-undo-<時間>`） |
| `--no-undo` | 不保存還原資料 |
| `--no-tags` / `--no-rename` | 只處理檔名／只處理標籤 |
| `--force-encoding ENC` | 舊編碼文字一律先用指定編碼解讀（`big5-uao`、`cp932`、`gbk`、`euc-jp`、`cp949`、`cp1252`、`utf-8`），解不開才自動偵測。適合確定整個資料夾都是同一種編碼時使用 |
| `--fix-ja-marks` | 還原標籤與檔名中，當年因 Big5 打不出來而代用的日文符號（見下方說明）。預設關閉 |
| `--skip-uncertain` | 含有低信心判定的檔案先不寫入，留待人工確認 |
| `--keep-mtime` | 保留檔案原本的修改時間 |

## 它做了什麼

### 標籤

1. 讀取檔案內所有標籤：ID3v2.2/2.3/2.4、ID3v1、APEv2。
2. **逐欄位**判定真正的編碼（同一個檔案的不同欄位可能是不同工具用不同編碼寫的）。
3. 合併成單一 ID3v2.4 UTF-8 標籤。欄位來源優先序：ID3v2 ＞ APEv2 ＞ ID3v1。
4. 移除 ID3v1、APEv2、Lyrics3（ID3v1 無法存放 UTF-8，留著只會讓讀它的播放器繼續顯示亂碼）。
5. 順便整理成 2.4 慣例：`TYER`/`TDAT` → `TDRC`（`20040923` → `2004-09-23`）、`(36)Game` → `Game`。

已經是乾淨 ID3v2.4 UTF-8 的檔案與沒有任何標籤的檔案不會被碰。

### 編碼判定

沒有統計式偵測器能可靠判斷一個只有幾個位元組的歌名，所以做法是：

- 用每一種候選編碼**嚴格**解碼，解不開的直接淘汰。
- 對解出來的文字評分：假名是否成詞、漢字在該語言的常用程度（借用 chardet 內建的字頻表）、括號是否成對、有沒有不該出現的字元……
- 用上下文打破平手：**檔名與目錄名**裡出現過的字、同一個檔案其他欄位的判定結果、同一個目錄其他檔案的判定結果。

Big5 一律用 UAO 對照表解碼。Python 內建的 `cp950`/`big5` 對假名區（`C6A1`–`C8FE`）的配置與實際檔案不同，會把 `ウンディ` 解成 `ヨ⑦Ыュ`。

### 無法還原的亂碼

有些標籤在過去已經被錯誤地轉換過兩次以上（例如日文以 EUC-KR 儲存 → 被當成 Shift_JIS 讀取 → 再轉成 Big5），過程中有些字已經變成 `□`，資訊不可逆地遺失了。這類欄位會：

- 標題：改用檔名回填（去掉開頭的曲序，`01_メイドさんパラパラ.mp3` → `メイドさんパラパラ`）；若 APEv2/ID3v1 有完好的標題則優先採用。
- 其他欄位：清除。

全部會列在報告的「無法還原而清除的欄位」區塊。

### 日文代用符號（`--fix-ja-marks`）

標準 Big5 沒有長音「ー」和中點「・」，當年的輸入法也打不出倚天擴充的那兩個字，所以很多標籤是用長得像的字代打的。這不是編碼問題（位元組解讀是正確的），而是內容本身用了別的字，所以要明確加上選項才會修改：

| 代用字 | 還原為 | 條件 |
|---|---|---|
| `一`（漢字的一）、`－`（全形連字號） | `ー` | 前一個字是片假名，且後面不是漢字（`ウンディ一ネ` → `ウンディーネ`、`スク－ル` → `スクール`） |
| `‧`（中文間隔號） | `・` | 該欄位含有假名，或檔名裡同一位置寫的是 `・`（`ラクス‧クライン` → `ラクス・クライン`） |

不會動的例子：`高瀨一矢`（人名）、`ガンダム一年戦争`（一年）、`アイテム一つ`（一つ）、`東京－大阪`、`湯姆‧克魯斯`（中文裡 `‧` 本來就是正確的字）。

標籤與檔名／目錄名都會套用（`09_メイドさんブギ－.mp3` → `09_メイドさんブギー.mp3`）；加上 `--no-rename` 就只修正標籤。標籤的每一筆修正會在報告中以「修正」列出前後對照，更名則列在「檔名與目錄名」區塊。

要留意的是，片假名之間的 `－` 一律當成長音。如果你的檔名習慣用全形連字號直接連接兩個片假名詞（例如 `スピッツ－チェリー.mp3`，中間沒有空白），它會被誤改成 `スピッツーチェリー.mp3`，請在預覽報告中確認更名清單。

### 檔名與目錄名

- **造字區（PUA）字元還原**：沒有安裝 UAO 的 Windows 會把 Big5 擴充字元（包含所有日文假名）轉成 U+E000–U+F848 的私用區字元，換一台電腦就變成方塊。這裡把它們換回真正的 Unicode 字元。
- **亂碼檔名修復**：檔名本身被用錯誤的字碼頁解讀（UTF-8 被當成 cp1252、Shift_JIS 被當成 Big5／cp437、GBK 被當成 Big5……）。證據充分才會更名；只有「可能是」的會列在報告裡當建議，不會動。同一個目錄裡只要有一個檔名能確定是哪一種誤讀，其餘的就比照處理。
- **Windows 問題字元**：結尾的空白或句點（檔案總管打不開）、零寬字元與雙向控制字元、保留裝置名稱（`CON`、`AUX`…）。

目標目錄本身不會被更名；目標名稱已存在時會略過並在報告中註明。

## 安全性

- **預設不寫入**，要加 `--apply`。
- **不在原檔上直接修改**：新檔（新標籤 + 原封不動的音訊資料）寫在旁邊，驗證音訊雜湊一致、標籤可正確讀回之後才取代原檔。中途當機或斷電，原檔仍然完好。
- **可完全還原**：還原資料保存每個檔案原本標籤的原始位元組與更名紀錄，`undo` 之後檔案與轉換前逐位元組相同。還原資料很小（只有標籤，不含音訊）。
- 取代檔案時保留原本的建立時間、屬性與 ACL。

## 已知限制

- 太短又沒有上下文的文字無法確定編碼。例如單獨一個 `絆` 字的 Shift_JIS 位元組同時也是合法的 Big5 字。這類判定會標成低信心列在報告裡。
- EUC-JP 與 GBK 的假名位置完全相同，漢字部分只能靠字頻區分；預設偏向 GBK（實務上 MP3 標籤極少使用 EUC-JP）。韓文短字串同理，預設偏向中日文。
- 當初轉成 Big5 時被換成繁體字的日文新字體不會改回去（`恋` → `戀`、`学` → `學`）；長音與中點可用 `--fix-ja-marks` 還原。
- `--fix-ja-marks` 只看前後文：沒有假名也沒有檔名佐證的 `‧` 會保留；片假名之間作為分隔用的 `－` 無法與長音區分。
- 更名後，`.m3u` 等播放清單裡記錄的舊檔名不會跟著更新。
- 只處理 MP3 的標籤；其他格式的檔案只檢查檔名。

## 開發

```bash
.venv\Scripts\python -m pip install -e .[dev]
```

```bash
.venv\Scripts\python -m pytest
```

| 模組 | 內容 |
|---|---|
| `charsets.py` | 嚴格解碼器、Big5-UAO、PUA 對應 |
| `plausibility.py` | 文字合理性評分（各語言設定檔） |
| `detect.py` | 編碼判定 |
| `tags.py` | 讀取所有標籤、規劃要寫入的 ID3v2.4 |
| `rewrite.py` | 安全寫入、還原、更名 |
| `names.py` | 檔名檢查與修復 |
| `japanese.py` | 日文代用符號還原（`--fix-ja-marks`） |
| `runner.py` | 走訪目錄、整合流程 |
| `undo.py` | 還原紀錄 |
| `report.py` / `cli.py` | 報告與命令列 |
